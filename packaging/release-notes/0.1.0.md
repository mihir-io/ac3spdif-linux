Dolby Digital Live and DTS Connect for Linux: captures all system audio, encodes it to AC-3 or DTS in real time, and bitstreams it over S/PDIF or HDMI as an IEC 61937 stream, so the receiver decodes 5.1 itself. First release.

## Install

| Package | For | Install |
|---|---|---|
| `ac3spdif-0.1.0-1.fc44.x86_64.rpm` | Fedora 44 and later | `sudo dnf install ./ac3spdif-0.1.0-1.fc44.x86_64.rpm` |
| `ac3spdif_0.1.0_amd64.deb` | Ubuntu 24.04 and later, Debian 13 | `sudo apt install ./ac3spdif_0.1.0_amd64.deb` |
| `org.ac3spdif.App.flatpak` | Any distribution with Flatpak | `flatpak install --user ./org.ac3spdif.App.flatpak` |

The RPM and the deb pull ffmpeg's libraries, PipeWire, ALSA, GLib, GTK and the appindicator from the standard repositories; nothing from RPM Fusion or a PPA is needed. The Flatpak is self-contained and fetches its runtime from Flathub.

Each package installs three programs:

- `ac3spdif-app`, the tray application: start and stop, pick devices and settings, watch buffer, drift and underrun figures live.
- `ac3spdif`, the command line, which can also run as a systemd user service from login with no UI.
- `ac3spdif-probe`, a dump of everything PipeWire and ALSA know about the digital outputs.

In the Flatpak the command line is `flatpak run --command=ac3spdif org.ac3spdif.App …` and the probe is `--command=ac3spdif-probe`. Service mode and launch-at-login work from inside it.

## Requirements

- PipeWire 1.0 or later with WirePlumber. The direct ALSA transport also works with no sound server at all.
- A digital output: S/PDIF (optical or coaxial) or HDMI. On HDMI the display or receiver must accept the codec.
- On GNOME, the AppIndicator extension for the tray icon (`gnome-shell-extension-appindicator`). KDE Plasma, XFCE, MATE and Cinnamon need nothing extra.

## What is in 0.1.0

- AC-3 at up to 640 kb/s and DTS at up to 1536 kb/s, 5.1 or stereo, encoded in-process with ffmpeg's libraries.
- Native PipeWire passthrough, or direct ALSA transport for the lowest latency.
- Clock drift correction between the capture and output clocks.
- A self-test tone per channel to verify the receiver end.
- Latency profiles from 2 to 12 bursts, and a `--dump` of exactly what went to the wire.

Verified end to end on an Intel HDA S/PDIF output under Fedora 44 with PipeWire 1.6.9. See the README for the full story and the latency figures.
